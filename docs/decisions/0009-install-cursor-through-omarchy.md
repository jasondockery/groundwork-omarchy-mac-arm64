# 0009. Install Cursor through Omarchy

When `cursor` is not already on `PATH`, this layer installs it the way Omarchy does. Older Omarchy Mac builds ship `omarchy-install-cursor`, which installs the aarch64 build and writes `~/.config/Cursor/argv.json` with `"password-store": "gnome-libsecret"`, the keyring Chromium and Electron need under Hyprland. This layer runs that command when it exists.

Omarchy Mac converged into upstream Omarchy on `quattro` (omacom/omarchy#14431), and current builds have no `omarchy-install-cursor`. Their Install menu runs `omarchy-install-and-launch Cursor cursor-bin cursor`, which adds the `cursor-bin` package (aarch64 in the Omarchy feed) and launches it. Without the older command, this layer runs `omarchy pkg add cursor-bin` and does not launch Cursor. Neither path relies on the package for the keyring setting; the step below adds it.

An existing `cursor` command stays installed. Setup does not download Omarchy's pinned AppImage over it and does not launch Cursor during `groundwork-update`. If `argv.json` has no `password-store`, setup adds `gnome-libsecret` and leaves the other keys unchanged. A password store that is already present stays as the user wrote it. Comments in that file are accepted. Adding the missing key rewrites the file as JSON. A file that already has the GNOME keyring setting is not rewritten, comments included. A symlink, a non-file, or text that is still not JSON after comments are removed stops setup without rewriting the file.
