# 0002. Edge via the Omarchy Mac Installer

The reference Apple Mac mini (M1, 2020) migrated on 2026-10-17. When this decision was made, that machine ran Omarchy `4.0.2-2` stable with a blank Super+Space menu, and Apple Silicon had only an edge channel. Omarchy 4.5 (released 2026-11-05 UTC) changed that: `default/pacman/aarch64-apple` now has edge, rc and stable files. rc was added first, and [omacom/omarchy#17498](https://github.com/omacom/omarchy/pull/17498) (merged 2026-11-04) lets `omarchy-channel-set stable` run on Apple Silicon. The installer publishes `catalog-rc` (2026-11-02) and `catalog-stable` (2026-11-05). Upstream kept edge as the default and says Macs are not moved. The PR warned that stable had no Mac kernel or boot packages until the rc → stable promotion ran. Checked 2026-11-17: that promotion has happened. `pkgs.omarchy.org/stable/aarch64` lists `linux-aurora 7.2.11.aurora14-1`, `m1n1-aurora 1.6.1.aurora22-1`, `omarchy-mac 0.2.3-2` and `omarchy-mac-boot 20261104-1`, and `catalog-stable` selects the Mac image `omarchy-mac-4.5.0-r2-2026.11.05-08c81abcef4f`. The stable feed has no `ffmpeg` carry, so the failure in [decision 0026](0026-ffmpeg-from-alarm-on-apple-silicon.md) does not happen there. This layer still stays on edge, because moving an installed edge Mac to stable is Jason's call and the 4.5 notes give no guidance for it. Edge is the `quattro` branch (`omarchy-dev 4.0.0.rNNNN`), which is ahead of the 4.5 release branch in new work. It may lack some fixes that exist only on the release branch. Revisit by 2026-12-15, or when upstream says how an edge Mac should move, or when edge stops getting fixes the stable line has. A move would be `omarchy-channel-set` run by Jason, not by this repo.

The chosen path is the newest upstream [Omarchy Mac Installer](https://github.com/omacom/omarchy-mac-installer) prerelease (2.3.16 on 2026-11-17) and its signed `edge` catalog, chosen explicitly because the app now opens on stable. The mini installed with installer `2.2.0` and image `omarchy-mac-edge-2026.10.14-79f8e36b977f` on 2026-10-17. That is a record of what this machine used, not a pin for later installs. Use the current signed catalog. The catalog's latest observed requirements and selected image, and the observed package state, are in [status](../status.md).

This is an OS install, not a package-channel switch or a `groundwork-mac` setup. The installer app refuses an existing Omarchy; Remove Omarchy first, which wipes the Linux install. [PR #46](https://github.com/omacom/omarchy-mac-installer/pull/46) (reinstall over an existing install) is still open. Start from the running Omarchy system, boot macOS once, and run the installer there. The `com.omarchy.mx` cleanup uses macOS `launchctl` and `defaults`. Those commands do not run inside Omarchy. Back up required data first.

After first boot, check the channel with `omarchy-channel-current` (`edge`) and run `omarchy update`. Super+Space and Super+K work on this path because [omarchy#14553](https://github.com/omacom/omarchy/pull/14553) is in `quattro`. [omarchy-mac#707](https://github.com/omacom/omarchy-mac/issues/707) and [PR #710](https://github.com/omacom/omarchy-mac/pull/710) cover only the omarchy-mac `quattro` path.
