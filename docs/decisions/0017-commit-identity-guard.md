# 0017. Install the commit identity guard from groundwork-core

The contract is groundwork-core `docs/commit-identity.md` (v0.10.0): no `Co-authored-by` trailer, and no author or committer that matches the local denylist. This layer installs the reference guard from the `core` pin.

## Decision

- **Scope is the user's own repositories, through `includeIf`.** `scripts/groundwork-commit-guard.py`, called by `scripts/apply-layer.sh` on setup and update, puts hooks in `~/.config/groundwork/git-hooks`. `commit-identity-guard.sh` there is a symlink to the pinned `core/commit-guard/commit-identity-guard.sh`, so the pin is the only copy. `core.hooksPath` is NOT set globally: a global path applied the personal-repo rules in work repositories (an employer-domain author or a pairing `Co-authored-by` was blocked there) and displaced hook tools such as pre-commit. Instead it lives in `~/.config/groundwork/commit-guard.gitconfig`, and `~/.config/git/config` includes that file through one `includeIf "hasconfig:remote.*.url:..."` entry per line of the pinned `core/commit-guard/owner-remote-patterns` (the list is data in core; `<owner>` becomes this user's name, one `[xX]` class per letter, so either case matches). Five patterns as of v0.10.0: `https://github.com/<owner>/**`, `git@github.com:<owner>/**`, `ssh://git@github.com/<owner>/**`, `*:<owner>/**` (any scp-style host alias such as `git@github-personal:<owner>/x.git`; `*` also crosses `@` and `:`) and `ssh://*/<owner>/**` (any `ssh://` host, with or without a port, and `ssh://` aliases such as `ssh://github-personal/<owner>/x`). The trailing `/` stops `<owner>2`, and `other/<owner>` does not match. If the list is missing from the pin or has no `<owner>` line, `apply` fails closed with a message and writes no scope. `apply` sets only the keys that are missing or different and removes nothing, so a machine installed on v0.9.0 gets the fifth key on the next run, and `doctor` warns that the scope is not set up until then. This needs git 2.36 or newer; older git gets one warning and no activation. `~/.gitconfig` and `~/.gitconfig.local` override the XDG file. If a `core.hooksPath` is set anywhere, setup prints one line and writes nothing, and the guard hooks stay inactive until the user chains `commit-msg` and `pre-push` from it.
- **Gaps, documented.** A push straight to an owned URL from a repository with no owned remote is not guarded. Remote URLs with userinfo (`https://user@github.com/...`) are not matched. A commit made before an owned remote exists is caught at `pre-push` once one is added. An owned repository with its own local `core.hooksPath` (husky, lefthook) bypasses the guard; `doctor` lists those under `~/code` (`GROUNDWORK_CODE_DIR` overrides). If the pinned guard symlink does not resolve, a hook prints one warning instead of skipping silently.
- **Per-repo hooks keep running.** Every documented hook name in the directory is a symlink to one dispatcher. For `commit-msg` and `pre-push` it runs the guard first (pre-push input is buffered and passed to both). Then it runs the repository's own `.git/hooks/<name>`.
- **Opt-out, recommended and implemented.** The guard is on by default, because the rule is meant to hold on every Groundwork machine. It changes global git behaviour and a work commit can legitimately carry another organization's trailer, so `groundwork-commit-guard off` creates `~/.config/groundwork/commit-guard-off`. The hooks check that file at run time, `apply` installs nothing and changes nothing while it exists, and `groundwork-commit-guard on` removes it. `GROUNDWORK_COMMIT_GUARD=off` bypasses one command. A blocked commit prints both ways out. The file is the saved choice, so `omarchy.json` is not involved.
- **Claude Code attribution.** `attribution.commit` and `attribution.pr` are set to `""` in `~/.claude/settings.json` (`CLAUDE_CONFIG_DIR` honored) only for keys that are absent. The merge keeps every other key, the file mode, and a symlink; writes a numbered `settings.json.bak.N` first; and leaves invalid JSON untouched.
- **Denylist.** An empty `~/.config/groundwork/commit-denylist` (`XDG_CONFIG_HOME` and `GROUNDWORK_COMMIT_DENYLIST` honored) is created when missing. This repository never supplies a value; names stay in that local file.
- **Doctor.** `groundwork-commit-guard doctor` (copied to `~/.local/bin` without replacing a foreign file) reports the scope, opt-out state and bypassing repositories, then the guard's own `doctor` output.

## Not covered

Cursor attribution is a UI setting that `doctor` cannot read. Pushing straight to a URL checks all reachable history (see the core doc).
