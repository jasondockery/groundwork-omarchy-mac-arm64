# 0023. TRIM through LUKS, a smaller locate index, and no per-directory zstd level

Checked against the reference machine's reported layout on 2026-11-08. Issue #145. This apply has not been run on the machine; the owner runs `./install.sh` or `update-all`. A package check is not that proof.

## Problem

The root filesystem is LUKS, `/dev/mapper/root`, with btrfs on top. The device-mapper discard granularity is 0B, so TRIM stops at the crypt device, and `fstrim.timer` is disabled. `plocate-updatedb.timer` runs daily and indexes the whole home directory, including every worktree's `node_modules`. The filesystem is mounted `compress=zstd:3`. A directory property cannot choose a different zstd level.

zram, swappiness, page-cluster, the CPU governor, and snapper are already fine. This decision does not change them.

## Decision

- **TRIM through LUKS uses the LUKS2 header, not Limine or crypttab.** This repo does not manage the boot chain. Limine and the crypttab that opens `root` stay in the `omarchy-mac` and `omarchy-mac-boot` packages. `cryptsetup refresh --allow-discards --persistent root` stores allow-discards in the open LUKS2 header and turns it on for the running mapping. A crypttab `discard` option would be a second copy of boot configuration this repo does not own. Discard reveals which encrypted blocks are free. That tradeoff is accepted so TRIM can run. The refresh runs only when `findmnt` shows `/` on `/dev/mapper/root` (a btrfs subvolume suffix is the same mapping), `lsblk` reports type `crypt`, and the discard granularity is `0`, `0B`, or `0b`. Any other size, including `10B`, counts as on. A token that is not a size does not count as on and does not start the timer. `--persistent` can replace flags already stored in the header. Before the first live run, read the Flags line from `cryptsetup luksDump` for this header. This change does not run that command.
- **`fstrim.timer` is enabled only after discards are on for `/dev/mapper/root`.** `systemctl enable --now fstrim.timer` follows a successful refresh, so the first trim sees discards. The packaged timer is weekly and persistent, so `--now` starts the timer unit and can schedule a catch-up trim. That command waits for the timer unit to start, not for the trim to finish. The helper gives that start 30 seconds. The passphrase prompt is a different wait: 300 seconds, the same window other prompts in this layer use, and the limit is printed before the prompt. The update stage has its own deadline. A timeout is a failed apply, not a slow success. A root `cryptsetup` that cannot be signalled may still be running after that failure. Another mapping name is left alone, and a root that is not `/dev/mapper/root` does not fail the doctor. If the refresh fails, `cryptsetup` is missing, or no terminal can ask for the passphrase, the timer stays disabled and this update fails. The next update asks again. A wrong passphrase is not saved as a decline. A refresh that leaves the granularity at zero, or a header that reports it cannot store allow-discards, is recorded in `/var/lib/groundwork/luks-discard-unsupported` and is not repeated; that record is written before the run says it will not retry, and deleting the file tries again. The next update then continues. A masked timer stays masked. `enabled-runtime`, `static`, and the other states `systemctl is-enabled` can print are left alone. Only `disabled` is enabled, and only once discards are on. Privileged commands stay in the same terminal session as the administrator prompt, so the credential from that prompt applies. A probe that does not need the credential uses its own session.
- **plocate keeps the distribution prunes.** `/etc/updatedb.conf` is a package file and is not edited. `config/plocate-updatedb.service.d.conf` is the only override. It replaces the service `ExecStart` with `/usr/bin/updatedb` plus `--add-prunenames` and `--add-prunepaths`. Those flags add to the package file; `--prunenames` and `--prunepaths` would replace it. The added names are `node_modules`, `.turbo`, and `.next`. The added paths are the setup account's `~/.t3/worktrees` and `~/.local/share/pnpm`. The committed file has `@HOME@`; apply writes the absolute home. The drop-in is one machine-wide unit for that setup account. A later apply by another account replaces those two paths. The tree stays free of account names (decision 0006). The drop-in lists only those two settings, each with a one-line reason. Package `Nice` and IO scheduling stay in the vendor unit.
- **A per-directory zstd level is not applied.** The kernel keeps only the algorithm from a directory compression property and takes the level from the mount. Files inherit that property from their direct parent only. Setting `zstd:1` on `~/.t3/worktrees`, `~/code`, or `~/.cache` would not change new files on a `compress=zstd:3` mount, and `btrfs property get` would still echo the stored string. On the reference machine the mount stays `compress=zstd:3`. Doctor reports the compress option `findmnt` actually prints and does not claim `compress=zstd:3` for a mount that does not set it. It does not ask for `btrfs-progs`, and it does not change the mount.
- **A plocate drop-in systemd has not loaded is installed again.** `systemctl daemon-reload` runs again when the file is already right but systemd does not list it. A missing `systemctl`, or a `systemctl show` that fails, is not treated as loaded.
- **`./install.sh` and `update-all` apply this** through `scripts/groundwork-storage.py`. The refresh reads the passphrase from the terminal, including when standard input is not that terminal. Without a terminal it prints `sudo cryptsetup refresh --allow-discards --persistent root`, says that the disk passphrase is separate from the administrator password, and does not change the LUKS header. Stopping at that prompt exits 130. `GROUNDWORK_STORAGE_ROOT` and `INSTALL_FIXTURE` are honored only when `GROUNDWORK_TESTING=1`, and a fixture root does not run the host's own binaries. A second run does not repeat a step that is already set. An update asks for administrator permission only when a privileged step is still pending, and says when a disk passphrase will be requested later. A timed-out or failed `findmnt`, `lsblk`, or `fstrim.timer` probe fails the apply. A missing command does not. A failed `systemctl show` for the plocate drop-in installs the drop-in again. `groundwork-doctor` checks TRIM, the locate drop-in, and the mount's compress option, and changes nothing. `update-all` stops that doctor at 15 seconds and discards its output. Probes the doctor can signal share an 8 second budget. A command stuck in uninterruptible sleep, or a root child that cannot be signalled, is outside that budget.

## Not done

- No live apply on the reference machine in this change. Doctor output from the machine, after the owner runs the apply, is the record that discards, the timer, and the drop-in are in place. The directory zstd level is not one of those records.
- No change if plocate's vendor unit starts passing its own `updatedb` arguments. Recheck the drop-in then. The package file would still supply `PRUNEFS` and `PRUNENAMES` through `--add-*`.
- No change to zram, swappiness, page-cluster, the CPU governor, or snapper.
