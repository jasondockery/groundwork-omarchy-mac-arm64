# Bitwarden: agent rules

Moved from `AGENTS.md`. Decision: [0014](../decisions/0014-offer-migration-to-omarchy-installers.md#bitwarden-desktop). Sign-in, Flatpak updates and removal: [apps guide](../apps.md).

- The default ensures Bitwarden CLI (`bw`). A new install uses Omarchy's `bitwarden` package when `pacman -Si bitwarden` finds it and the package passes the checks in decision 0014. The user-scoped aarch64 Flathub app `com.bitwarden.desktop` is the fallback only when that feed has no `bitwarden` package. An existing native `bitwarden` is reused. An existing user Flatpak stays until the offer-only `bitwarden-flatpak` migration. Setup and `update-all` do not update that Flatpak while the feed has `bitwarden`.
- Count Omarchy's `bitwarden` package only when `pacman -Qoq` names `bitwarden` as owner of the `bitwarden` on `PATH` and its ELF files pass the page-size check. Drop it only when the same run added it, and remember the failed version in `bitwarden-rejected.json` until the feed changes. While that version is the one in the feed, setup does not install the Flatpak in its place.
- After a decline, setup prints the one reminder line from decision 0014. Updates stay quiet about that decline. Once the `bitwarden` package owns the `bitwarden` command, the feed-watch brief does not offer Bitwarden.
- For installed Chromium, register only the official Bitwarden extension through its external manifest under `/usr/share/chromium/extensions`, preserving different previous manifests with numbered backups. Do not impose forced-install policy, rewrite profile databases, or authenticate accounts. Browser approval and effective autofill remain first-use acceptance.
