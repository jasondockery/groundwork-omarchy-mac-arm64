# Agents

This repo is a personal layer for Omarchy on Apple Silicon (aarch64). It is meant to be shared. Read these files before changing anything:

- The original `groundwork` curriculum and north star for shared learning material. Curriculum stays there for now. The `core/` submodule is a read-only groundwork-core checkout. `./install.sh` and `update-all` run `git submodule update --init -- core` before apply, and that checkout is required for the Brave spec. Do not copy those pages, or `core/browser/brave.json`, into this repo.
- `README.md` for what this environment installs and how.
- `docs/status.md` for the current state of the reference machine.
- `docs/decisions/` for choices that are already made.
- `docs/keybindings.md` and `docs/remote-access.md` for first-run learning and private access.

Shared engineering guidance belongs to Compass, projected here under `.compass/` (read `.compass/COMPASS.md` and `.compass/TERMINOLOGY.md` for substantial engineering changes instead of inventing a competing local doctrine). Load `skills/reviewable-agent-workspaces/SKILL.md` for workspace ownership, `skills/concurrent-agent-runtimes/SKILL.md` before starting or inspecting concurrent processes, and `skills/repeatable-agent-execution/SKILL.md` before the first edit in a checkout and before final proof. The optional skills this repository selected are listed in `compass.skills.json` and live under `skills/`; load the one that matches the work. GitHub writes follow `repo-contribution-etiquette`. Dependency policy extends the shared [renovate-config](https://github.com/jasondockery/renovate-config) preset; configuration alone does not prove central-runner coverage.

## Rules

- The desktop comes from `omacom/omarchy` (`quattro`), packaged as `omarchy-dev` from `pkgs.omarchy.org/edge`. Apple Silicon support is the `omarchy-mac` and `omarchy-mac-boot` packages from `omacom/omarchy-mac-pkgs`. The shared Apple Silicon hardware and desktop code converged into `omacom/omarchy` itself ([omacom/omarchy#14431](https://github.com/omacom/omarchy/pull/14431), merged 2026-10-10 UTC); the Mac's own hardware defaults and services, and its boot chain, stay in those two packages. `omacom/omarchy-mac` is the legacy fork: its `quattro` branch is not what the installer uses, and per the omarchy-mac-pkgs README it stays only to deliver a standalone migration script, proposed in [omacom/omarchy-mac#690](https://github.com/omacom/omarchy-mac/pull/690) (still open on 2026-10-28). Do not copy stock Hyprland templates, shell aliases, tmux config, or git defaults into this repo.
- Preserve Omarchy's desktop navigation, tmux, terminal, editor, shell, and AI-tool defaults. Do not add a replacement keybinding or tmux config unless Jason explicitly asks for it. The trackpad override and keyd Caps Lock tap-Escape/hold-Control default are intentional. `--without-keyd` skips keyd setup without disabling an existing service. See `docs/decisions/0007-learn-omarchy-defaults.md`.
- Do not run `chezmoi apply` from `groundwork-mac` on an Omarchy machine. See `docs/decisions/0001-do-not-apply-groundwork-on-omarchy.md`.
- `./install.sh` stows only `packages/hypr`, installs Herdr/Tailscale/keyd, and installs Cursor when `cursor` is absent, through `omarchy-install-cursor` on older Omarchy Mac builds and otherwise `omarchy pkg add cursor-bin`. An existing `cursor` command is kept. When `~/.config/Cursor/argv.json` has no `password-store`, setup adds `gnome-libsecret` and leaves every other key unchanged. It ensures missing native AI providers through Omarchy's declared mise tools, enables the Tailscale and keyd daemons, and reconciles the newest official T3 Code Nightly CLI on each run, including existing stable installations, except on kernels with pages larger than 4 KiB, where it keeps a Nightly that already starts and otherwise pins `0.1.2-nightly.20261021.3499`. On those kernels `update-all` checks every ELF file in a newer build with `readelf -lW`, smoke-runs that candidate under bubblewrap with a scrubbed environment, a core limit of 1 (the only limit a piped core pattern treats as do-not-dump), and a timeout (a missing bwrap skips that run with a warning and does not execute it), installs exactly the version whose `--version` matches, remembers misaligned builds and signal/`PinnedRuntimeInstallError` failures in `t3-rejected.json`, warns without remembering timeouts or transport errors, reports a failed `t3 update` that leaves a working install as a warning, and repairs a T3 that no longer starts (pingdotgg/t3code#23433). It backs up a different existing keyd config and reloads the mapping on every default install. It does not stow `core/`, it does not write `/usr/share/omarchy`, and it installs Blip only when `--with-blip` is passed. Tailnet sign-in stays interactive and local. Shared Tailscale policy lives in `groundwork-core/docs/tailscale.md`; this repo owns only the Omarchy service and enrollment steps.
- The reference M1 Mac mini migrated on 2026-10-17 through the Omarchy Mac Installer and signed edge catalog (installer 2.2.0 and image `omarchy-mac-edge-2026.10.14-79f8e36b977f` on that day). Apple Silicon has only an edge channel. See `README.md` and decision `docs/decisions/0002-edge-via-omarchy-mac-installer.md`. This repo only applies user settings and never installs the OS. Keep the actual installed version in machine/status notes.
- Upstream bugs stay upstream. Desktop, shell, binding, and shared-helper bugs go to `omacom/omarchy`. Apple Silicon package bugs, including the Mac's hardware services and boot chain in the `omarchy-mac` and `omarchy-mac-boot` packages, go to `omacom/omarchy-mac-pkgs`. Package recipes, signing, and publication go to `omacom/omarchy-pkgs`. Installer app or install image bugs go to `omacom/omarchy-mac-installer`. A hardware qualification report goes to [omarchy-m-testing.org](https://omarchy-m-testing.org), not a bug tracker. `omacom/omarchy-mac` is the legacy fork: it still has a bug template, and it does not take new package or hardware bugs. Leave a report already filed there where it is. Link to them. Do not refile them here.
- Config that is stowed must work on any Apple Silicon Mac: Mac mini, MacBook Air, and MacBook Pro, M1 and later. `./install.sh` refuses a machine that is not aarch64. Machine-specific facts go in `docs/machines/`.
- Never commit private keys, account emails, employer or org remotes, Wi-Fi names, or Tailscale addresses. Public SSH keys do not belong here either. Put account-specific Git and SSH config on the machine, outside this repo. Do not publish while an old commit still contains any of that.
- `packages.txt` is optional Arch packages. Do not add Linuxbrew.
- The default also ensures Obsidian and Bitwarden CLI (`bw`), reuses a native Bitwarden desktop or an existing user Flatpak, and otherwise installs Omarchy's `bitwarden` package when `pacman -Si bitwarden` finds it and it passes the checks in decision 0014, with its user-scoped aarch64 Flathub app as the fallback. It installs FreeTube the same way (`io.freetubeapp.FreeTube`) and leaves FreeTube settings and `~/.var/app/io.freetubeapp.FreeTube/config/FreeTube` alone. `docs/apps.md` owns sign-in, Flatpak updates/removal, and cross-platform notes guidance. `scripts/seed-obsidian.py` seeds Vim mode only when app settings are absent; never automatically move notes, replace existing settings, enable broad community plugins, or enroll a cloud account. `GROUNDWORK_OBSIDIAN_VAULT` selects an actual local folder. Blip (`nixfred.blip`) is an opt-in iMessage client (`./install.sh --with-blip`, off by default, decision 0011). A default run and `--without-blip` leave an existing Blip install alone. Install it from git with `omarchy plugin add`, and move it into the shared plugin list once that list supports git-URL sources and per-entry opt-in. The installer does not run `blip-setup` or record a gateway name. Its bun preflight downloads the mise-selected `bun-linux-aarch64` release over https, verifies `SHASUMS256.txt`, and calls the T3 `load_alignments` helper before `omarchy-install-dev-env`. Session-restoration plugins remain outside the defaults.
- Detect, report, and offer a move to Omarchy's own installer; never force one (decision 0014). Only `y` or `yes`, in any case, at the `./install.sh` prompt (stdin, stdout, and stderr on the terminal; bounded to 300 seconds, after setup choices are saved) or `./install.sh --migrate-to-omarchy-installers` migrates. Updates and other runs print one line naming the current and preferred methods and the migration id. A decline is saved as `declined_migrations` in `omarchy.json`. When Omarchy has no installer for an app, nothing is offered. New offers go through `offer_omarchy_migration`. Never pass `--delete-data` or remove app data. Count Omarchy's `bitwarden` package only when `pacman -Qoq` names `bitwarden` as owner of the `bitwarden` on `PATH` and its ELF files pass the page-size check; drop it only when the same run added it, and remember the failed version in `bitwarden-rejected.json` until the feed changes. Cursor is report-only: never touch a pacman-owned `cursor-bin`, and only print a manual-move notice for a `cursor` no package owns.
- For installed Chromium, register only the official Bitwarden extension through its external manifest under `/usr/share/chromium/extensions`, preserving different previous manifests with numbered backups. Do not impose forced-install policy, rewrite profile databases, or authenticate accounts. Browser approval and effective autofill remain first-use acceptance.
- Brave is offered through `omarchy-install-browser brave` when that installer lists `brave` (decision 0015). Keep Chromium. Setup and update check out `core` with `git submodule update --init -- core` after a fast-forward and before apply. `apply-layer.sh` runs that checkout when `core/browser/brave.json` is missing, so an `update-all` still running the updater from the previous apply can fast-forward onto this revision. A core worktree left at the previous gitlink is not a local change; edits inside `core` are. Write `core/browser/brave.json` (groundwork-core tag `v0.7.0`) to `/etc/brave/policies/managed/groundwork.json` as `root:root` mode `0644`, and chown that tree when the bytes already match. Do not keep a second copy of the spec or of the extension manifest. Offer Bitwarden only (`nngceckbapebfimnlniiiahkandclblb`); do not add a forced-install policy. Remember a `brave-bin` that fails the page-size check or crashes on launch in `brave-rejected.json`, and remove it only when this run added it. A launch timeout or other non-signal failure is not remembered and is not removed, and an update retries that launch without sudo when the policy is already current. Ctrl+C during the launch check exits 130 and does not remember the version. The launch sets `RLIMIT_CORE` to 1 so a piped core pattern does not store a crash dump. When Brave is already the default, a failed recheck says so and names `omarchy-default-browser chromium`. An existing `brave-rejected.json` or `brave-accepted.json` that is not a regular file of page size to version lists stops setup before install. Do not install Brave Origin, a Brave Flatpak, or pass a pooled-pages workaround. Do not delete `~/.config/BraveSoftware` or `~/.var/app/com.brave.Browser`. Save a declined migration before publishing policy.
- Default desktop sharing uses WayVNC via the Groundwork-owned user service/helper. Generate and preserve local credentials, wait for an online Tailscale IPv4 address, and bind only that address. When its unit, helper, or WayVNC config changed and `WAYLAND_DISPLAY` is unset (SSH or cron), an inactive unit stays stopped and the restart record is cleared. When `WAYLAND_DISPLAY` is set, the unit restarts even if it is inactive. Print the session-drop warning only when a restart actually runs. See `docs/remote-access.md`. Never expose legacy Apple-compatible VNC authentication on LAN/all interfaces, publish credentials, disable the lock screen, or claim pre-login/headless recovery. `--without-screen-sharing` leaves an existing setup alone; shared port policy stays in Core. WayVNC's private keymap makes Apple Screen Sharing's Command follow existing Super bindings and Option follow existing Alt bindings. Leave Omarchy's global keymap and attached keyboards unchanged.
- Shell plugins come from the shared groundwork-core list (`omarchy/plugins.json`) and are applied once by `scripts/omarchy-plugins.py` after the Hyprland reload. `GROUNDWORK_PLUGIN_LIST` overrides that https source. `omarchy-plugins.exclude.json` and `~/.config/groundwork/omarchy-plugins.exclude.json` skip ids, each with a reason. `update-all` updates listed checkouts; `groundwork-update` leaves their revisions unchanged. Do not name plugin ids in this repo, do not Stow `~/.config/omarchy/shell.json`, do not re-enable a plugin whose directory already exists or a built-in already recorded, and keep plugin swaps in the list's `replaces` field rather than in code. Undoing a swap turns a replaced id back on only when this layer turned it off. If `mouse.lua` or `omacontrol.lua` sets `touchpad.natural_scroll` differently from the stowed `input.lua`, the file loaded later wins. If `hyprland.lua` does not load that file, the stowed `input.lua` still applies. See `docs/decisions/0010-omarchy-plugins-from-shared-list.md`.
- Local inference is off unless `./install.sh --with-local-inference` is passed (decision 0012). That installs Omarchy edge `ollama` and `ollama-vulkan`, plus `vulkan-tools` when `vulkaninfo` is missing. It downloads no model and does not enable `ollama.service`. GPU use is unverified until `scripts/verify-local-inference.py run` is executed on the machine. Shared model policy stays in groundwork-core#19. `omarchy-mlx` and macOS MLX are not installed.
- Syncthing is a default (decision 0013, contract in `groundwork-core/docs/syncthing.md`). `scripts/groundwork-syncthing.py` owns the apply and `groundwork syncthing-pair`. Never set `STGUIADDRESS` or `--gui-address`, never leave Syncthing on the upstream `default` listen addresses, never PUT a default folder object over an existing folder, never pause or unpause `groundwork-shared`, and never write a device ID, API key or Tailscale address into this repo. The FreeTube wrapper is not implemented yet. Tests use a fake Syncthing; they are not proof of the real REST API, 16 KiB pages or cross-machine sync.
- Run `bash -n install.sh scripts/apply-layer.sh scripts/migrate-from-groundwork.sh` and `python3 -B -m unittest discover -s tests -v` before handing off installer changes. Fixture success is not live desktop/input or cross-machine acceptance. Never mark machine status as installed or authenticated from package presence alone.
- Independent review of a pull request expects 2 rounds and stops at a hard ceiling of 4. At the ceiling, the open findings go to Jason, who decides. Rounds count as `skills/independent-code-review/SKILL.md` defines them: a new head, reviewer, or publication does not reset the count. Hosted automated review keeps its own budget (Jason, 2026-10-28).

## Layout

| Path | Role |
|---|---|
| `core/` | Read-only groundwork-core submodule. `./install.sh` and `update-all` run `git submodule update --init -- core` before apply. Not stowed onto the machine. Do not copy `browser/brave.json` into this repo. |
| `packages/hypr/` | Stow package. Personal Hyprland overrides only. |
| `keyd/default.conf` | Default Caps Lock tap = Escape, hold = Control. Skip setup with `./install.sh --without-keyd`. |
| `docs/decisions/` | One decision per file. Update the decision instead of appending a journal. |
| `docs/status.md` | Replace this when the reference machine's state changes. |
| `docs/machines/` | One file per computer. |
| `scripts/omarchy-plugins.py` | Applies the shared Omarchy shell-plugin list. |
| `scripts/groundwork-syncthing.py` | Syncthing apply (tailnet listeners, shared folders) and `groundwork syncthing-pair`. Copied to `~/.local/bin/groundwork-syncthing`. |
| `scripts/verify-local-inference.py` | Opt-in M1 GPU check for Ollama Vulkan. A passing run on hardware is the record; the repo does not contain one. |
| `docs/local-inference.md` | Apple Silicon install, proof, update, stop, and removal. |
| `omarchy-plugins.exclude.json` | Plugin ids this layer skips, each with a reason. |
